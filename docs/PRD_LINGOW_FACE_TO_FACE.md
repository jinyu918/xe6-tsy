## 2. 产品概述

Lingow 面对面双语交流面向同一物理空间内的临时交流。用户选择一组语言对，使用已有音频终端开始会话；系统在这组语言内识别当前发言语言，将内容翻译成另一种语言，并通过译音或企业微信投递帮助双方继续交流。

P0 只解决当前这一场交流，不要求登录、注册、参与者登记或历史会话管理。字幕是可选展示，音频是主链路。

## 3. 背景与问题

### 3.1 用户问题

| 问题 | 影响 |
| --- | --- |
| 双方没有共同语言 | 无法自然开始和持续交流 |
| 交流是临时发生的 | 登录、注册、资料登记会增加准备成本 |
| 译音过长会占用交流时间 | 对方必须等待播放完成才能继续讲话 |
| 语言可能在交流中变化 | 固定配置无法覆盖当前会话 |

### 3.2 产品机会

以会话级语言配置和实时音频链路完成最短闭环：选择语言对、开始交流、获得译音或投递、继续交流、结束会话。

## 4. 目标与成功标准

### 4.1 P0 目标

在不要求参与者登录、注册或登记的前提下，让通常为两人的临时面对面交流完成稳定的双语听译闭环。

### 4.2 产品成功标准

- 用户可以在一个活动会话中完成多轮双语交流。
- 会话开始前选择的语言对决定本轮可识别的语言范围；系统不要求用户标记说话人。
- 用户可以在同一活动会话中修改语言对或输出方式，修改从下一 Turn 生效。
- 双向模式下双方都能听到目标语言译音。
- 单向模式下，一种语言方向播放译音，另一种语言方向的每个有效 FinalTurn 逐句发送到已绑定的企业微信目标。
- 播放停止、有效新发言打断、网络断开和单轮 Provider 失败不会制造重复事实或重复投递。
- 页面或设备没有大屏幕时，音频主链路仍可完成。

P0 期不承诺固定翻译质量、生产并发、端到端延迟或真实硬件覆盖范围；这些指标由工程验证和发布配置另行冻结。

## 5. 用户与场景

### 5.1 用户角色

| 角色 | 定义 | P0 权限 |
| --- | --- | --- |
| 会话发起人 | 创建并控制当前临时会话的人；在单向模式中是投递接收方 | 创建、启动、修改配置、停止播放、结束会话 |
| 共同交流者 | 与会话发起人在同一物理空间交流的人 | 通过同一终端参与音频交流，不需要账号或资料 |

“主人”和“另一方”是输出路由的产品称呼，不代表系统识别或保存现实身份、声纹或说话人编号。

### 5.2 典型场景

1. 两个人选择中文和英文，轮流讲话，双方都听到另一种语言的译音。
2. 会话发起人选择单向输出：主人语言方向播放译音，另一语言方向的译文逐句发送到已绑定的企业微信。
3. 会话持续数小时，用户在中途修改语言对，修改在当前 Turn 完成后生效。
4. 译音播放时出现有效的新发言，当前译音停止并处理新 Turn；咳嗽、笑声、环境噪声和短暂杂音不触发打断。

## 6. 产品范围

### 6.1 P0：双语听译闭环

- 未登录临时会话的创建、连接、启动和结束。
- 会话开始前选择一组受支持的语言对。
- 活动会话内修改语言对和输出方式，下一 Turn 生效。
- WebRTC 音频采集、VAD、ASR、翻译、TTS 和播放。
- 在当前语言对内自动识别每个 Turn 的发言语言，并翻译成另一种语言。
- 双方都听译文、主人投递加另一方听译两种输出方式。
- 企业微信目标的存在性和可用性校验；P0 只消费设置中已绑定的目标。
- 单向模式下有效 FinalTurn 的逐句异步投递。
- 听音、处理、播放、投递、打断、失败和结束状态。
- 显式停止、有效新发言打断、幂等重试和错误恢复。
- 文本 FinalTurn、UsageFact 和投递状态事实。
- 有屏幕端的可选原文、译文和状态展示。

### 6.2 P1：已存在但不属于 P0 核心闭环

- assistant 模式及其与 interpretation 的模式切换。
- 唤醒词、命令窗口和结构化语音命令。
- 设备正式身份和 Mobile 控制面扩展。

### 6.3 P2：账户化与长句增强

- 手机号登录、账户数据隔离和长期数据归属。
- 企业微信目标绑定管理、历史会话、用量工作区和多实例控制面。
- 长句自动字幕投递、流式 ASR partial、稳定短语、流式翻译和流式 TTS。
- 长句达到阈值后的字幕优先降级和投递失败后的 TTS 回放。

### 6.4 P0 不做

- 会话内说话人识别、匿名发言者编号、声纹身份和现实身份绑定。
- 跨会话声纹、长期参与者档案和参与者资料管理。
- 超出当前语言对的全局语言识别。
- 多人同时发言分离、会议仲裁和多设备会议。
- 强制字幕、历史会话列表和“切换会话”功能。
- 行业知识、政策材料、检索增强、个人术语库、声音克隆、音色选择和人工纠错。
- 管理后台、订单、支付、发票和硬件制造。
- 原始音频持久化或用户侧原始音频回放。

## 7. 核心产品规则

1. P0 不要求登录；临时会话通过短期票据、会话绑定和连接所有权校验保护。
2. 一次开始操作只创建一个业务会话；重复请求返回第一次结果，不创建第二个活动会话。
3. 会话开始前必须确定语言对；活动会话允许修改语言对和输出方式。
4. 语言配置修改从下一 Turn 生效；已打开 Turn 使用开始时的配置快照。
5. 每个 Turn 只在当前语言对内自动识别发言语言，并翻译成另一种语言；识别结果不表示说话人身份。
6. 双向模式要求两个语言方向都可用 TTS。
7. 单向模式要求设置中存在已绑定、已验证且启用的企业微信目标；没有目标时单向模式不可启用。
8. 单向模式按有效 FinalTurn 逐句创建不可变投递快照，异步发送不阻塞采集、识别、翻译或另一方向播放。
9. 投递状态至少包括 `queued`、`sending`、`retrying`、`sent` 和 `failed`。
10. 显式停止按 `playback_id` 精确生效；重复停止是幂等操作，迟到音频不得恢复播放。
11. 播放中收到有效新发言时停止当前译音并进入新 Turn；咳嗽、笑声、环境噪声和短暂杂音不触发打断。
12. 空音频、纯噪声、空文本和纯标点不生成 FinalTurn，不调用翻译或投递。
13. Provider 单轮失败只影响当前 Turn；会话保持可恢复状态时允许继续下一 Turn。
14. P0 保存文本 FinalTurn 和用量事实，禁止持久化原始音频。
15. 所有 Create、Start、End、配置更新、FinalTurn 消费、投递和播放停止操作必须支持稳定幂等身份。

## 8. 用户流程

### 8.1 创建并开始会话

```text
打开临时会话入口
  -> 读取可用语言目录
  -> 选择语言对
  -> 选择输出方式
  -> 单向模式校验企业微信目标
  -> 请求麦克风权限
  -> 创建临时会话并取得短期票据
  -> 建立实时连接
  -> 启动会话
  -> 进入听音状态
```

### 8.2 普通 Turn

```text
听音
  -> VAD 检测发言
  -> 在当前语言对内识别发言语言
  -> 翻译成另一种语言
  -> 双向模式播放译音
     或单向模式按语言方向播放/投递
  -> 保存文本 FinalTurn 和 UsageFact
  -> 播放或投递完成后回到听音
```

### 8.3 修改语言配置

```text
活动会话
  -> 用户选择新的语言对或输出方式
  -> 服务端校验 expected_version 和企业微信目标
  -> 更新配置版本
  -> 当前 Turn 继续使用旧快照
  -> 下一 Turn 使用新配置
```

版本冲突时服务端拒绝覆盖，客户端读取最新版本后重新提交。

### 8.4 结束会话

```text
活动会话
  -> 用户点击结束或离开页面
  -> 停止本地采集和播放
  -> 幂等 End
  -> 服务端释放实时资源
  -> 会话进入 ended
```

## 9. 页面与交互要求

### 9.1 页面组成

P0 页面只服务当前临时会话，包括：

- 语言对选择。
- 输出方式选择。
- 开始和结束会话。
- 当前连接和运行状态。
- 可选文本区域。
- 投递状态区域。
- 停止当前播报。

P0 不提供历史会话列表、跨会话跳转或任意投递地址输入。

### 9.2 状态与动作

| 状态 | 用户可见结果 | 可执行动作 |
| --- | --- | --- |
| 未授权 | 需要麦克风权限 | 授权、查看设备设置 |
| 连接中 | 正在连接 | 等待、取消 |
| 已连接未启动 | 显示语言对和输出方式 | 开始、修改配置、结束 |
| 听音 | 可以继续讲话 | 修改下一 Turn 配置、结束 |
| 处理 | 正在识别和翻译 | 等待、结束 |
| 播放 | 正在播放译音 | 停止播报、结束 |
| 投递中 | 正在发送企业微信消息 | 等待、结束 |
| 已打断 | 当前译音已停止 | 继续交流、结束 |
| 失败 | 显示失败类别 | 重试、重新开始、结束 |
| 结束 | 音频资源已释放 | 返回临时会话入口 |

无屏幕设备必须通过音频提示或设备状态信号承载开始、停止、失败、重试和结束，不得要求字幕才能完成主流程。

## 10. 状态模型

### 10.1 业务会话状态

```text
created -> connecting -> active -> ending -> ended
created/connecting/active -> failed
```

`services/api` 管理业务会话状态。`ended` 和 `failed` 是终态；End 未得到 realtime 确认时，不得提前写入 `ended`。

### 10.2 实时运行状态

```text
idle -> listening -> processing -> playing
playing -> listening
playing -> interrupted -> listening
processing -> failed -> listening
active -> ending -> ended
```

进入 `processing` 前，realtime 必须在当前语言对内确定 source/target 语言。无法确定、超出语言对或没有有效语音时进入 `discarded`，不生成 FinalTurn。

### 10.3 配置版本状态

```text
version N active -> version N superseded
```

配置快照不可修改；新版本替代旧版本，已打开 Turn 不受影响。

### 10.4 投递状态

```text
queued -> sending -> sent
queued/sending -> retrying -> sending
sending -> failed
```

投递状态不改变已经保存的翻译事实。

## 11. 功能需求

### FR-01 临时会话

- 未登录用户可以创建临时会话。
- 创建不要求参与者名单、姓名、声纹或账号。
- 创建、启动和结束支持幂等；重复开始不得产生第二个活动会话。
- 会话结束后再次开始创建新会话，不提供会话切换或历史入口。

### FR-02 语言配置

- 客户端从服务端能力目录选择语言对。
- 语言对必须同时满足 ASR、翻译和目标语言 TTS 能力。
- 活动会话保存版本化配置，包括语言对、输出方式和生效边界。
- 配置更新使用 `expected_version`；冲突不覆盖服务端最新版本。
- 每个 Turn 在当前语言对内自动识别发言语言；不生成说话人身份。

### FR-03 实时音频处理

- 使用 WebRTC 采集和播放音频。
- 使用 VAD 确定发言窗口和结束边界。
- Turn 固定开始时的语言配置、识别结果、输出模式和路由快照。
- 空音频、纯噪声、空文本和纯标点不进入翻译或投递。
- Provider 失败隔离在当前 Turn 内，并向客户端返回可恢复错误。

### FR-04 双向听译

- 两种语言方向均可执行 ASR、翻译、FinalTurn 保存和目标语言 TTS。
- 播放完成后回到听音状态。
- TTS 失败时保留已生成文本事实并显示播放失败，不静默改变输出模式。

### FR-05 单向听译与企业微信投递

- 单向模式只为一个配置语言方向播放译音。
- 另一个配置语言方向的每个有效 FinalTurn 自动生成一条企业微信投递。
- 投递内容为不可变原文/译文快照，目标只引用设置中已绑定且已验证的 `target_ref`。
- 投递异步执行，不阻塞音频采集、ASR、翻译和另一方向播放。
- 没有可用企业微信目标时，拒绝启用单向模式，并提示先绑定目标。
- 投递失败保留 FinalTurn 和失败状态，不静默回退为双向模式。

### FR-06 播放控制与打断

- 显式停止按 `playback_id` 精确停止当前和排队音频。
- 重复停止同一播放为幂等无操作。
- 迟到音频不得重新开始播放。
- 有效新发言到达时停止当前译音并开始新 Turn；噪声、咳嗽、笑声和短暂杂音不打断。
- 停止播放不回滚已提交的 FinalTurn 或 UsageFact。

### FR-07 状态和错误反馈

- 客户端至少区分未授权、连接中、已连接未启动、听音、处理、播放、投递中、已打断、失败和结束。
- 每个可恢复错误都提供重试、重新开始或结束动作。
- 错误信息只展示稳定错误类别，不泄露其他会话、token、Provider 密钥或完整目标地址。

### FR-08 事实、幂等和可观测性

- 保存文本 FinalTurn、UsageFact、配置版本变化、会话生命周期、播放停止和投递状态。
- FinalTurn 文本事实不可变；UsageFact 只追加。
- 企业微信逐句投递幂等身份至少包含 `turn_id`、渠道和 `target_ref`。
- 同一幂等键与相同 payload 重放返回原结果；payload 不同返回冲突。
- 记录 ASR、翻译、TTS、投递、播放打断、FinalTurn 接收和失败阶段耗时。
- 指标不得包含原始语音文本、手机号、token 或完整目标地址。

## 12. 数据与权限

### 12.1 数据对象

| 对象 | 关键字段 | 规则 |
| --- | --- | --- |
| TemporarySession | `session_id`、状态、时间、配置版本、短期票据引用 | 生命周期内可变，结束后不可重新激活 |
| LanguageConfigSnapshot | 版本、语言对、输出方式、路由、生效边界 | 快照不可修改，新版本替代 |
| Turn | `turn_id`、`session_id`、source/target language、配置版本、原文、译文、时间 | 文本事实不可变，不包含说话人身份 |
| Playback | `playback_id`、`turn_id`、状态、generation | 状态可变，generation 防止迟到音频 |
| DeliveryMessage | `message_id`、`channel=wecom`、`target_ref`、`turn_id`、内容快照、状态 | 目标不向客户端暴露完整地址，内容不可变 |
| UsageFact | `event_id`、服务类型、耗时、Provider、模型 | 只追加，不更新 |

P0 不创建 Participant、SpeakerProfile、SpeakerAttribution、跨会话声纹或原始音频对象。

### 12.2 权限

| 操作 | P0 临时会话 |
| --- | --- |
| 创建会话 | 允许 |
| 查看当前会话状态 | 仅当前会话票据允许 |
| 修改语言配置 | 仅当前活动会话发起端允许 |
| 启动/结束会话 | 仅当前活动会话发起端允许 |
| 停止播放 | 当前连接且匹配 `playback_id` 允许 |
| 创建企业微信投递 | 仅持有会话票据且引用已绑定目标允许 |
| 读取其他会话 | 拒绝 |
| 访问原始音频 | 不提供，且不保存 |

## 13. 接口与系统边界

接口字段、状态、错误码和事件以 `packages/contracts` 为唯一来源。

| 接口/事件 | 责任方 | 用途 |
| --- | --- | --- |
| Temporary Session Create/Start/End | API | 会话生命周期和短期票据 |
| Language Config GET/POST | API | 能力目录、语言对和输出方式；使用 `expected_version` |
| Realtime Ticket | API | 建立绑定当前会话的实时连接 |
| WebRTC offer/ICE/start/stop | Realtime | 媒体连接和运行控制 |
| Runtime State | Realtime | 听音、处理、播放、打断和失败状态 |
| Playback Stop/Interrupt | Realtime | 按 `playback_id` 幂等停止 |
| FinalTurn | Realtime -> API | 文本事实、投递源和质量排查 |
| UsageFact | Realtime -> API | 用量和阶段耗时 |
| Outbound Message | API/Delivery Worker | 企业微信逐句投递和异步重试 |

API 负责业务会话、配置、长期事实和投递；realtime 负责 WebRTC、音频、VAD、ASR、翻译、TTS、播放和运行状态；客户端只负责采集、播放、交互和状态展示。

## 14. 异常与边界处理

| 场景 | 必须行为 |
| --- | --- |
| 麦克风拒绝或设备不存在 | 不创建音频上行，展示设备或授权错误 |
| 语言对不支持 | 保存配置前拒绝，不调用 Provider |
| 无法确定或超出当前语言对 | 不进入翻译，不生成 FinalTurn，回到听音 |
| 语言配置版本冲突 | 返回冲突，保持服务端最新版本 |
| 空语音、纯噪声、纯标点 | 不生成 FinalTurn，回到听音 |
| ASR/翻译/TTS 失败 | 当前 Turn 失败并提供重试，会话按运行状态决定是否继续 |
| 企业微信目标缺失或不可用 | 单向模式不可启用；已有 FinalTurn 保留，不静默回退 |
| 投递超时或失败 | 使用原幂等身份重试，状态进入 `retrying` 或 `failed` |
| 播放中显式停止 | 停止当前及排队音频，不回滚文本事实 |
| 播放中有效新发言 | 停止当前译音并处理新 Turn |
| 播放中噪声/咳嗽/笑声 | 不打断当前译音 |
| 网络断开 | 保留可恢复状态，不自动创建第二条 PeerConnection |
| 重复 Create/Start/End/Stop | 返回第一次结果，不重复创建、释放或播放 |
| 页面刷新 | 停止旧本地采集，使用原票据尝试恢复；失败则回到新会话入口 |
| 页面关闭或返回 | 尽力停止采集并幂等 End，服务端回收孤立资源 |
| 同一票据第二连接 | 拒绝第二连接并保留原连接 |
| 同时说话 | 不做语音分离或仲裁，不作为 P0 质量承诺 |

## 15. 非功能要求

### 15.1 安全与隐私

- 临时会话票据短期有效，并绑定会话、连接和播放归属。
- 客户端不能自定义 `session ownership`、`account identity` 或 `playback ownership`。
- 投递目标脱敏存储和展示；客户端不能读取完整目标地址。
- P0 禁止持久化原始音频，不提供原始音频回放。
- 日志和指标不得记录原始语音文本、手机号、token、Provider 密钥或完整目标地址。

### 15.2 稳定性与可观测性

- 会话可持续数分钟到数小时；不设置产品层固定最大时长。
- 服务端必须通过连接租约、孤立资源回收和容量控制保障长会话。
- 记录会话创建/启动/结束、连接建立/断开、Turn 各阶段耗时、Provider 失败、播放打断、投递状态和重复消费。
- 真实 Provider、mock Provider、浏览器、网络和音频设备矩阵必须分别验证。

### 15.3 性能

正式性能指标由发布评审冻结，至少包括：首次连接耗时、说话结束到译音开始的 p50/p95/p99、数小时会话资源稳定性、投递队列恢复时间和错误率。

Issue #301 的 40 会话结果只能作为固定双节点、mock Provider 环境的验证证据，不能直接作为生产 SLA。

## 16. 验收标准

### 16.1 P0

| ID | 验收结果 |
| --- | --- |
| AC-P0-01 | 未登录用户可以选择有效语言对，使用短期票据创建并启动临时会话。 |
| AC-P0-02 | 同一活动会话修改语言配置后，已打开 Turn 使用旧快照，下一 Turn 使用新版本，过程中不创建第二个会话。 |
| AC-P0-03 | 每个 Turn 在当前语言对内自动识别发言语言并翻译成另一种语言；无法确定或超出语言对时不翻译、不生成身份数据。 |
| AC-P0-04 | 双向模式下两个语言方向都完成 ASR、翻译、FinalTurn 保存和目标语言 TTS。 |
| AC-P0-05 | 单向模式下一个语言方向播放译音，另一个语言方向的每个有效 FinalTurn 自动生成一条发送到已绑定企业微信的不可变投递。 |
| AC-P0-06 | 没有已绑定且已验证的企业微信目标时，单向配置被拒绝，界面提示先绑定目标，不静默回退。 |
| AC-P0-07 | 无可用大屏幕时，音频主链路仍能完成；字幕缺失不判定失败。 |
| AC-P0-08 | 显式停止和有效新发言能够停止当前及排队播放；重复停止无错误，迟到音频不恢复；噪声、咳嗽、笑声和短暂杂音不打断。 |
| AC-P0-09 | ASR、翻译、TTS 或投递单轮失败不伪造成功，并提供重试或继续会话的动作。 |
| AC-P0-10 | 重复 Create、Start、End、配置更新、Stop 和 FinalTurn 消费不产生重复会话、事实、计费或投递。 |
| AC-P0-11 | P0 不创建 Participant、SpeakerProfile、匿名发言者编号、跨会话身份或原始音频对象。 |
| AC-P0-12 | P0 没有历史会话列表或切换会话入口；结束后再次开始创建新临时会话。 |
| AC-P0-13 | 客户端能够区分未授权、连接中、已连接未启动、听音、处理、播放、投递中、已打断、失败和结束，并为可恢复失败提供动作。 |
